# River Water Levels (riverwaterlevels.com)

## Line 0: the reader first (HARD, owner 2026-10-18: "make that line 0")
Every decision, page, block, widget, rule and release is judged by one question: **does a person standing at the river, on a phone, understand every condition of this river in seconds and trust it?** Not "is it correct" (necessary, never enough), not "does it pass the gate". Concretely:
- The first screen answers, without scrolling: how much water, how it compares with normal, which way it is moving, what is coming (forecast, alerts, rain), and how old the data is. `check.py` enforces the first-screen contract (tiles for flow, gage height, comparison with the date's record and 24 h change come before the first data block).
- Look before you build: study the best competing pages (Lakebrief, USGS, NWS, American Whitewater) as screenshots, then design; view every change as a screenshot at 390 px and 1280 px, light and dark, before it ships.
- Widgets over tables where a picture says it faster (dial, trend arrow, sparkline, stage ladder, heatmap); tables keep the exact numbers and sources.
- Plain words, units everywhere, abbreviations explained on hover and in the glossary, a safety line next to the numbers.
- Every feature is tested against a person: a paddler, an angler, a flood watcher, a first-time visitor. If a page serves the rules but not the person, the rules are changed or the page is rebuilt, never the person blamed.
- Rules in this file are enforced in code, not left as notes. Enforced today: `check.py` (source line per block, units and gauge-local time, first-screen tiles, no jargon in headings or stat tiles, no empty widget, every image sized and with alt text, heading order, no sentence stated twice; 13 broken fixtures in `--selftest` must all fail), `ui_gates.mjs` (390 px first screen, tap targets, text contrast in light and dark, minimum text size, no sideways scroll, console errors; saves a contact sheet to `shots/gate/` that a person LOOKS at before any release; runs inside `refresh.py` on the PC as a logged, non-blocking step so fresh data is never held back), `render_test.mjs`, `js_test.mjs`, `tests.py`, and `tools/watchdog.py` (hourly GitHub workflow on the LIVE site: build older than 3 h, stale readings or too few pages fails and emails the owner). Not enforced yet: unit toggle (not built, US readers use cfs and feet), per-block widgets exist for alerts, upstream strip, rain, snowpack and watershed only.

## Hard rules
- **No composed prose or verdicts on data pages.** Visible text is a source value with unit and time, a label from `lib/render.py`, or a verbatim source string (escaped). No "good time to fish", no safety judgement, no ranking sentences.
- **Every block has a `Source:` line** (what, who, when fetched or observed). A block that has no data returns `None` (no heading, no source line).
- **Terms gating:** a block renders only if its source in `data/sources.json` has status `quoted` or `owner-permission`; `off` sources are built but never shown. New source = search for its terms (WebSearch, not WebFetch), quote them in `sources.json`, then build.
- **Freshness:** flow older than 24 h = page rebuilt with a "Gauge not reporting" notice at the top; older than 30 days = CriticalFail (page not rebuilt, last release stays live); forecast 12 h amber / 72 h hidden; weather obs 3 h / 12 h; rain 6 h / 24 h; alerts amber at 3 h; SNOTEL 5 days; CPC 3 days.
- **`collect.py` is the only code that touches the network.** `build.py` reads `cache/` only. A failed source keeps its previous cache value.
- **Percentile** = interpolation of USGS daily percentiles for the date, shown with "estimated"; never presented as a USGS value. Time zones: gauge-local with abbreviation.
- Every published gauge page is indexable once the hold is lifted; no noindex gate, no 410. Trust, hub, state pages in the sitemap; sitemap = page set (check.py enforces).
- No API keys in pages, zips or docs. Key lives in the calcscrape `.env`, read only by `lib/common.py`.
- Owner is a non-coder: do the work, plain short replies, never ask them to run commands. Verify live pages before saying "live". One zip for ChatGPT reviews, key-scanned.

## Pipeline
`python -I collect.py [site..]` (all 25 = wave 0) -> `python -I build.py` (to `dist_next/`) -> `python -I check.py` -> `python -I publish.py` (atomic swap to `dist/`, previous in `dist_prev/`, `--rollback`) -> `npx wrangler deploy` -> `python -I livecheck.py <urls>`.
`python -I refresh.py` runs all of it with a lock and a log (`runs/refresh.log`). `python -I tests.py` = safety tests (determinism, stale source, rollback, block safety). `node js_test.mjs` = page JavaScript against stubbed USGS responses (CSV complete and sorted, no partial file on a 429, live-refresh note); `node render_test.mjs [--shots]` = real-browser overflow, console, scripts-off at 390 and 1280 px.
Collector modes: `--fast` (bulk USGS latest incl. related gauges, NWS, NWPS, rain: every 30 min), `--nws-only`, `--extras-only [--keys=a,b]` (slow sources). Full `collect.py` only every 6 h. Two scheduled tasks (hidden, only while the owner is logged in): "RiverWaterLevels Fast Refresh" (`refresh.py --fast`, 30 min) and "RiverWaterLevels Refresh" (`refresh.py`, 6 h). For manual deploys run `python -I refresh.py --fast` so the lock stops collisions. `python -I build.py --preview` builds dist_preview/ with uncleared blocks visible (review only). USGS rate-limits bursts (429).

## Page template (frozen "final form")
Gauge page (one page, rebuilt 2026-10-18 and 2026-10-19), top to bottom: alert banner when the NWS has an active alert; stat tiles (latest flow and gage height with 24 h sparklines, comparison with past years in plain words Below normal / Normal range / Above normal plus "Higher than N% of the years on record for this date" and a dial, 24 h change, NWS alerts only when there are none, forecast high, water temperature, air temperature with wind and gusts, upstream tile, rain, sunset); jump links; then what is happening now and next (weather alerts, 7 days, gage height with flood-stage ladder, rate of rise, hourly forecast when there is no Forecast page, 3-period weather, radar, water quality sensors, water temperature by month, SNOTEL); a heading "How today compares with past years" (30 days, 12 months, same 50 days in earlier years, comparison with the gauge's record); three CLOSED groups (`<details class="fold">`): Flood record and history (peaks, flood stages by year, flood frequency, historic crests, flood impacts, long-range outlook, storm events, federal declarations), Daily values, measurements and rating, Watershed, water quality and land. A jump link, permalink or shared #anchor opens the group holding it (`FOLD_JS`, tested in `js_test.mjs`); printing opens all. Right column (below the content on a phone): upstream and downstream strip, other gauges nearby (up to five within 150 miles), NWS forecast point, map, official pages, about the gauge. Forecast page (only where NWS issues a river forecast): river forecast or model guidance, rain, outlooks, hourly heatmap, weather, air, sun. Tools row: Save gauge (localStorage), CSV download. Phone: one column, tables with four or more visible columns become stacked label-and-value rows (`table()` adds `data-l` and class `stk`), jump links scroll sideways in one row, ladder drawn 420 units wide so labels stay readable. Not built: unit toggle, "My levels" widget (reader types their own low and high flow for their activity; stored in the browser, no advice from us).
